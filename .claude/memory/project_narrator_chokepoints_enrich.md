**da#353 root cause CORRECTED 2026-07-09** (original diagnosis was wrong; it is NOT "batch skips `hadith_node_id`"). `data/raw/sanadset/sanadset.csv` header is `Hadith,Book,Num_hadith,Matn,Sanad,Sanad_Length`; the parser looks for `hadith_id|id|Hadith_ID` and `book_id|book|Book_ID` → **both null in 650,986/650,986 rows** (76% of the 853k corpus). `books.csv` has only a `Book` column (956 names, **no id**) so `_parse_books` returns `{}` → `has_books=False` → **da#219 never activated**. `collection_name` then falls back to the CSV stem `"sanadset"` == `_SOURCE_CORPUS`, so `source_id = sanadset:sanadset:0:0:{row_offset}` — a *legitimate* `corpus:collection` id that only **looks** double-prefixed. `_collapse_double_corpus` eats the collection segment (16M+ warns) but introduces **0 collisions** (650,986 → 650,986 distinct) — nothing is corrupted today.
