- [memory-judge over-flags fully-stale](feedback_memory_judge_overflags_fully_stale.md) — the Haiku staleness judge's fully-stale bucket is CANDIDATES TO VERIFY, never a delete list: 18 flags / 18 false positives across W28 + #1139 (placeholders, child-repo + external refs, deliberately-absent files, `section_*.md` category errors). - [A corpus misses its constant dimension](feedback_corpus_misses_its_constant_dimension.md) — a differential finds defects only where it VARIES; the held-constant axis is invisible by construction. #1193's 85-shape/7,616-command sweep proved 0 weakened while 24 fail-open holes sat in the one axis it fixed (payload shape). Knowing the rule doesn't prevent it — I repeated it while verifying the reviewer who found it. Enumerate axes, don't just pass. **Cheapest detector (#1269): score the candidate you rejected — 3 charsets scored an identical `420 passed`, so the suite pinned none of them.** Also: mutation-test your OWN new fixtures (`assertIsNotNone` passes when the parser fails by returning a wrong value), and scope a blast-radius survey to the artifact's consumers (parent-repo-only survey said 0; org-wide said 77). **And CROSS the axes, don't only vary them (#1325): both were in the list and individually varied; the uncrossed cell held three defects. Discriminator — run the CORRECTED implementation as a mutant; if it survives the whole suite while moving real verdicts, the corpus cannot tell the two apart.** W29.
- [A PR-body table is a claim](feedback_pr_body_table_is_a_claim.md) — verify-before-claim applies to measurement tables in PR bodies/reports, not just status claims: code+tests get run while prose gets written from memory. #1277's "main → exit 0" row was never measured (inverted from the issue body); truth was worse. A worked example inside an ISSUE is the author's claim too — re-run it. PR-body edits are silent; correct with a visible comment. W29.
- [Both ends tested, the join untested](feedback_both_ends_tested_join_untested.md) — a value produced in A and consumed in B can have both ends covered while the hand-off is not: deleting `unknown.extend(drift_unknown)` left 75/75 green and turned a total registry outage into "no drift". Mutate the PLUMBING, not just the logic. Sibling: a fixture that REPLACES an adapter can never test that adapter — keep one test driving the real one. W29 #1295.
- [An equivalent mutant is not an inert test](feedback_equivalent_mutant_is_not_an_inert_test.md) — a surviving mutant may be semantically EQUIVALENT (the edit changed nothing), which is indistinguishable from "guard untested" in the output. `\w*`→`\w*?` before a trailing `\b` corrupts nothing; the real corruption needed lazy quantifier AND dropped anchor. Probe the mutated function directly before filing. A wrong repro attached to a right finding manufactures a false negative for the next checker. W29 #1302.
- [Allowlist membership needs adversarial measurement](feedback_allowlist_membership_needs_adversarial_measurement.md) — when an allowlist IS the safety boundary, each member must be measured at its adversarial edge, not its common invocation. `sort` shipped as "inert" until `--compress-program` was shown to execute its stdin (real shell, both bash and zsh). Probe flags taking a COMMAND as a value. Also diff the membership set against org policy — the same list allowlisted `grep` while the org hard-blocks it (#1008) and omitted the mandated `rg`. Second instance one round later: a CONTEXTUAL premise (`rg --pre` cannot fire with no input PATH) fails when the attacker supplies `/dev/stdin` — grade the PREMISE, not just the measurement; and a policy argument is never a safety argument. Third instance — the MECHANISM: rg was admitted on a GREEN CI that measured nothing, because ripgrep is not installed on the runner and `expect_runs=False` passes vacuously when the binary is absent. Directional: a missing tool silently passes rows that ADMIT a member and loudly fails rows that EXCLUDE one. Remedy is install AND guard, never guard alone. GENERAL RULE: a negative row cannot detect its own instrument breaking, so it is only trustworthy when a POSITIVE row in the same class shares that instrument — a member whose measurement can never fail equals a member with no measurement. W29 #1316/#1318.
- [A prose guarantee never traced to its mechanism](feedback_prose_guarantee_vs_mechanism.md) — W29's dominant defect: a property STATED in a step name, docstring, test name or PR body and never re-derived from the code meant to honor it. One detection method (trace the claim end-to-end), four distinct SITES with different remedies — producer (`|| true`, cannot emit a negative signal), scope (#1318: fires and can fail, measures a narrower property than claimed), consumer (traces.jsonl — both documented consumers told not to read it), consumer-ex-ante ("informational unless outcome.raised" — no consumer ever built). Sharpest instance: a CI step named "exit 0 on empty stdin" that pipes `{}` — valid JSON, not empty stdin — so even deleting `|| true` leaves it testing the wrong thing; a second lock on a door already in the wrong wall. Corollaries: a PARTLY-toothless job is more dangerous than a uniformly toothless one (the working half lends credibility to the broken half); repairing such a step requires RENAMING it; a stale-LOOKING reason is worse than a missing one (it invites the confident action it was meant to block). Reading is exactly the activity that cannot detect this class. W29 #1330/#1329/#1331/#1332.
- [State the denominator with the number](feedback_state_the_denominator_with_the_number.md) — three collisions in ONE review round, each two CORRECT counts under different denominators (11 vs 9 stragglers; 33 vs 30 files; two `_check_and_log` exemplars both real). A wrong number gets challenged; a right-under-a-different-denominator number gets ABSORBED, because each party verifies their own and attributes the mismatch to the other. More checking cannot help — both already checked. Fix is one phrase: carry the population inside the number ("31 converted onto `_hook_main`", "34 in the line-count glob"). Survives having both numbers correct in your own head — the orchestrator held both and still relayed one under the other's denominator. When counts disagree, first hypothesis is different denominators, not error: reconcile by deriving the delta (11 = 9 + 2 dispatchers), and put the reconciliation in the ARTIFACT, not just the thread. W29 #1330.
- [The test-refactor triple](feedback_test_refactor_triple.md) — for ANY test refactor, three checks must ALL be unmoved: collected count + sorted node-ID identity + PER-FILE assertion density (AST-count `assert` + `self.assert*`). Count alone is preserved by a refactor that keeps the functions and guts the bodies; ids too. Only assertion density falsifies that directly, and it must be per-file — a total stays constant while one file gains and another loses. Measured at W29 #1333: 2772 collected, ids identical, 4282/4282 assertions with zero per-file diffs, held across six heads. Cheap (~1 min, three passes) so "too large to check" is never the reason it wasn't run — largeness is the argument FOR it. Necessary not sufficient: pair with a mutation check driven THROUGH the refactored path, and a standalone per-file sweep (an aggregate run masks import-order bugs — a file passing only because an alphabetically-earlier one already put a dir on sys.path). Parametrisation trap: structurally identical ≠ safely mergeable; a normaliser stripping string constants over-groups (one 102-member "group" where the literal WAS the test). W29 #1333/#1117.
- [Flag precision decays with age](feedback_flag_precision_decays_with_age.md) — a conservative classifier's FLAGGED list is candidates to verify, and its false-positive rate RISES with the age of what it classifies: `check_worktree_merged.py` scored 1 correct (the fresh squash — the #1212 fallback working as designed) / 4 false across one 2026-08-09 sweep, split exactly along age, because the content-equivalence test decays as main moves and the same content lands under a different commit. Not a defect — the bias is deliberate and Step 0 never force-removes, so a false UNMERGED costs a stale directory while a false `merged` costs work. The counterintuitive part: the list is LEAST reliable precisely when it is LONGEST, so the condition that tempts a bulk force-remove is the one where bulk action is least safe. Verify blobs, reset DIRTY to HEAD first to keep removal non-force. Sibling of [[feedback_memory_judge_overflags_fully_stale]].
- [An annunaki record is not a hook failure](feedback_annunaki_record_is_not_a_hook_failure.md) — `hook:` in `errors.jsonl` names the WRITER, not a failing hook: 52 `annunaki_monitor` records read as "the monitor errored 52 times" were all `exit_code: 0` / `category: masked-failure`, 35 of them genuine catches, and the monitor never threw. Second trap in the same file: `_is_content_display`'s verb allowlist omits `gh run view` / `rg`-over-a-log and `2>&1` disqualifies suppression outright, so READING a CI log mints `confidence: high` records — one already-fixed failure produced 17 (33% of the class). The false class scales with how hard a bug was to debug, so the artifact meant to surface unsolved problems over-weights solved ones. Group by underlying failure signature, not by `hook:`; check the cited bug is still live. Same shape one level up: a `skip_*` action record is a NOTICE naming its remediation, not a silent miss — I called one a fail-open by analogy to a sibling class and re-verification refuted it. W29 #1354.
