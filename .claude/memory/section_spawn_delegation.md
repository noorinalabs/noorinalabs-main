- [Spawn worktree follows orchestrator cwd](feedback_spawn_worktree_follows_orchestrator_cwd.md) — refines the above: the worktree is based off whatever repo the orchestrator's PERSISTENT Bash cwd is in, not always the parent. A stray `cd` into a child repo silently strands the next isolated spawn. Verify `rev-parse --show-toplevel` in every brief. W29.
- [Cross-spawn cwd collision](feedback_cwd_collision_cross_spawn.md) — two agents sharing one cwd on different branches: 2nd checkout moves the 1st → commits on wrong branch.
- [Shared-worktree review revert hazard](feedback_shared_worktree_review_revert_hazard.md) — ≥2 reviewers on one implementer worktree collide: one's revert-to-test corrupts the other's view. Review from an isolated checkout at the committed head SHA. #1056/#1058.
- [Scratchpad is shared across agents](feedback_scratchpad_shared_across_agents.md) — the session scratchpad path is per-SESSION, not per-agent; concurrent agents writing `mutate.py` clobber each other silently and can report each other's mutation tables. Always brief a namespaced subdir (`scratchpad/<initials>-<issue>/`). W29, 6 concurrent implementers.
- [Ontology-context spawn gate](feedback_ontology_context_spawn_gate.md) — worktree-isolated spawns BLOCK (exit 2) without a literal `## Ontology Context` heading in the prompt; "tell the agent to run the librarian" does NOT satisfy it. Trap: the gate exempts any brief opening `You are X, Program Director|Manager|TPM|Project Lead|Release Coordinator`, so persona title — not task — silently decides whether it applies. #1264.
- [Orchestrator may spawn freely](feedback_orchestrator_may_spawn_freely.md) — owner lifted the "don't spawn unless asked" session guidance (2026-08-03, W29 retro): spawn whatever team the charter/skill names, no permission ask. Hub-and-spoke, model tier, and brief discipline still bind — permission does not. (The `team_name: "noorinalabs"` clause this note used to carry was retired by #1375: the parameter is deprecated and ignored, and a hook now blocks it.)
- [pre-commit stash reverts a concurrent agent's edits](feedback_precommit_stash_reverts_concurrent_edits.md) — two writers in one worktree: A's pre-commit-gated commit stashes/restores B's UNCOMMITTED edits to unrelated files; a failed restore silently reverts them with a clean `git status`. Explicit pathspecs do NOT protect. Own worktree per writer; re-read after editing. W29 retro, observed.
- [No head SHA in review briefs](feedback_no_head_sha_in_review_briefs.md) — send the PR number, never a head SHA. The reviewer must re-confirm head at post time per evidence-standards, so a baked SHA is only ever older — a second, worse source of truth. W30 #1388: both SHAs handed to the reviewer were stale on arrival (branch moved twice; the *correction* was stale too, written from a cached read). Applies to mid-review corrections as well: send "head moved", not a new SHA.
- [Agent liveness signals are unreliable](feedback_agent_liveness_signals_are_unreliable.md) — `ListAgents` showed zero subagents while a reviewer was still working (respawned it → two full Opus reviews of one diff); 7 agents finished without reporting, one having posted a ChangesRequested nobody saw. And a posted verdict ≠ a counted one (#1413). One rule: run `resolve_review_verdicts` and report `distinct_reviewers` — never agent self-reports, never eyeballed comment counts. W30.
- [Shared scratchpad collides across agents](feedback_shared_scratchpad_collides_across_agents.md) — all agents in a session share ONE scratchpad dir. W30 collided 3×: a `--body-file` read another agent's file so a PR carried the wrong story's body with `Closes <wrong-issue>`; a sandbox's relative path resolution escaped into the scratchpad and imported a stale production-named module, so mutation testing passed with a metachar deleted. Namespace every scratch file by PR/issue; never reuse a real module's basename; read back before consuming; assert `module.__file__` in sandboxes.
- [Relay a reviewer's list verbatim](feedback_relay_a_reviewer_list_verbatim.md) — renumbering or re-describing a reviewer's must-fix items substitutes one requirement for another, and the author AND the second reviewer both inherit the substitution as fact. W30 #1425: the gate's F7 (marked *not required*) was relayed as "F6" and required; the real F6 never reached anyone, survived, and collided with the author's own F4 fix ("3 of the 6" true vs "3 of the 11" false, ~400 lines apart). Same shape as [[feedback_pr_review_verdict_format]] §8 one level up — load-bearing tokens are the item numbers. Reviewers: on re-review, check your OWN list against what landed.
- [Child-repo spawns must be non-isolated](feedback_child_repo_spawn_no_isolation.md) — `isolation: worktree` fences an agent to a PARENT worktree and the harness then refuses EVERY git op against a nested child repo (`git -C`, `cd &&`, `EnterWorktree`), even with `dangerouslyDisableSandbox` — all 7 child-repo spawns failed at W28 kickoff. Spawn child-repo implementers NON-isolated, each building its own worktree inside the child clone; keep isolation for parent-repo spawns. **The charter still mandates the broken form** (`orchestration-model.md` § Spawn Isolation Default).
- [Commit identity roster resolves from cwd](feedback_commit_identity_roster_from_cwd.md) — the identity gate picks which repo's `roster.json` to validate against from the shell's process CWD, NOT the `git -C <path>` target; a valid author is rejected against the wrong repo's roster with a misleading member list. `cd` into the worktree before committing. Bash cwd persists between calls, so one stray `cd` sets it.
