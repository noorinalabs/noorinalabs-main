- [A typo'd short flag consumes the next token](feedback_short_flag_consumes_next_token.md) — a flag that TAKES AN ARGUMENT does not error when mistyped; it silently eats the next token and becomes a different, well-formed command. `rg -rl PATTERN .` is valid and means "replace each match with the literal string `l`" — it returned 1.9 MB of mangled lines instead of a file list. THE TELL: plausible-but-odd output from a command that should have returned a structurally different shape (filenames, a count). There is no error. It had already garbled an earlier sweep that was seen and written off as a display artifact — do not explain away odd output on first sighting. Ask "is this the SHAPE this flag combination produces?", not "does this look wrong?". Generalises to every argument-taking short flag (`-e -f -o -r -C -S --pre --compress-program`) — same mechanism that makes `sort --compress-program` exploitable. Prefer long flags in committed commands. Belongs in docs/TOOLCHAIN.md § Text search via PR. W29.
